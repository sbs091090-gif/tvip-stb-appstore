# Архитектура и границы проверки

Клиент → Nginx → Gunicorn/Django → PostgreSQL (только управление и фоновая сборка).
APK, иконки, баннеры и скриншоты обслуживает Nginx из общего media volume.
Веб-процесс не публикует порт наружу. Nginx перезаписывает X-Real-IP и
X-Forwarded-For: заголовки клиента не определяют выбранную версию.

В каждом worker отдельный бинарный radix tree IPv4/IPv6. При сборке для каждого
узла заранее формируются JSON и SHA-256 ETag; одинаковые варианты используют
одни и те же bytes. Правила разных приложений наследуются независимо.
При конфликте подсетей одного приложения побеждает наиболее длинный префикс.
Если правила нет, используется единственная default-версия. Приложения без
подходящей версии отсутствуют в каталоге. Выключенная версия не используется.
Выбор — не более 32/128 переходов, без SQL и сериализации JSON на запросе.

Снимок считывается транзакцией REPEATABLE READ и заменяется одним присваиванием
после полной сборки. Обновление — каждые 2 секунды; воркеры обновляются независимо.
При ошибке БД сохраняется последний успешный снимок, ошибка записывается в лог.
На холодном запуске каталог и healthz возвращают 503 до первой успешной сборки.
Изменения через Django admin обновляют временную метку StoreSettings; прямые SQL
изменения не поддерживаются как способ публикации. Тело каталога также участвует
в ETag, поэтому несколько изменений в одну секунду различаются.

HTTP: GET/HEAD /catalog.json, ETag/If-None-Match (включая weak и wildcard),
private/no-cache для предотвращения общего кеша между IP-сегментами.
Формат protoVersion=1 основан на JSON, предоставленном пользователем.
Управление: /admin/ со штатной авторизацией, CSRF и журналом Django admin.
Файлы хранятся под случайными именами; APK проверяется по manifest/package,
извлекаются versionName/versionCode/minSdk/permissions, размер и SHA-256.
Баннеры проверяются на 16:9. Извлечение manifest не является проверкой
криптографической подписи APK или гарантией безопасности его кода.

## Эксплуатация

Перед внешней публикацией настройте DNS, HTTPS, ALLOWED_HOSTS и PUBLIC_BASE_URL.
По умолчанию порт доступен только на loopback хоста. Для внешнего доступа задайте
HTTP_BIND и настройте TLS на доверенном шлюзе или в Nginx. Если перед Nginx есть
балансировщик, добавьте set_real_ip_from только для его конкретных адресов и
real_ip_header; не доверяйте заголовкам от произвольных источников.
Для админки через HTTPS задайте SECURE_COOKIES=true и CSRF_TRUSTED_ORIGINS, затем
настройте TLS в Nginx. В текущем варианте HTTP нужен
для локальной разработки и проверки Android STB; публичная админка требует TLS.

Сохраняйте резервные копии PostgreSQL и media вместе. Не удаляйте Compose volumes
при обычном обновлении. Удаление записи не удаляет APK с диска: старые URL остаются
доступными для уже начавшихся загрузок. Сборку мусора выполняйте отдельно после
периода удержания и проверки ссылок. Пароли и .env не включаются в Git или образ.

Цель 30 000 STB не означает 30 000 запросов в секунду: при интервале 3600 секунд
средняя частота около 8,3 запросов/с, но синхронный старт создаёт всплески.
Проверки разработки не подтверждают производственный SLA. Перед эксплуатацией
нужны нагрузочные испытания с реальным каталогом, CIDR, APK, диском и сетью;
измерения p95/p99, пропускной способности скачивания и поведения при рестарте/сбое БД.
Также требуется проверка на настоящей TVIP S-Box Android 4.4.1+.
